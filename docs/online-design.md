# 온라인 대전 설계

서버 없이(정적 호스팅만) 방 코드로 2~4명이 붙는다. GitHub Pages 에서는 공개 MQTT 중계, Claude 아티팩트에서는 `room` 기능을 쓴다.

## 한 줄 요약
**모든 기기가 같은 엔진을 같은 시드로 돌리고, 사람이 고르는 순간의 "입력"만 주고받는다.** 판 상태는 보내지 않는다.

## 왜 상태 전송이 아니라 입력 전송인가
- 아티팩트 `room` 의 presence·메시지는 한 번에 4 KiB 까지다. 판 상태는 중반에도 약 8 KiB(압축 2.4 KiB)라 쪼개 보내야 한다.
- 호스트가 상태를 정해 보내면 호스트가 주사위를 조작할 수 있고, 호스트가 나가면 판이 끝난다.
- 입력은 항목당 10~20바이트이고, 엔진은 이미 규칙 코드가 화면과 분리되어 있어 같은 입력이면 같은 결과가 나온다(시험으로 확인).

## 구조
```
전송 계층 (transports.js)  내 상태 올리기 / 남들 상태 받기 — 탭(BroadcastChannel) · Claude room · MQTT
방 프로토콜 (room.js)      방 코드·정원·시드 합의·입력 기록 복제·해시 대조 (DOM 없이 Node 에서 시험)
세션 (session.js)          연결 생명주기, 저장·복귀, 나가기, 연결 끊긴 사람 대신 AI
브리지 (bridge.js)         엔진의 "사람 입력" 지점을 기록으로 바꿔 끼움, 되감기(재생)
엔진 (rules.js 외)         결정적: 난수는 rand() 하나로, 알까기는 고정 간격 계산
```

## 상태 객체 (참가자마다 하나, 최신본만 전달)
`a` 앱 표지 · `s` 내 id · `n` 이름 · `t` 갱신 번호 · (방장) `cr ph ep cf ro` · `cm rv` 시드 합의 · `g` 시작 정보 ·
`hv` 각 사람의 입력 줄을 몇 개까지 받았는지 · `e c rl` 입력 창 · `hs` 판 해시.
받은 값은 모두 `cleanState` 로 거른다(모르는 필드 버림, 숫자 범위, 문자열 길이·글자, 방 id 모양).

## 입력 기록
사람마다 자기 줄(stream)에만 쓴다. 항목은 `[종류, a, b]`.
- `[0, k, 값]` k 번째 입력에 대한 답 (k 는 엔진이 사람 입력을 받은 순번, 모든 기기에서 같음)
- `[1, 좌석, k]` 좌석을 k 번째 입력부터 AI 로 (나가기·대신 두기)

값은 선택지 번호, 말 id, 칸 번호, `t`(던지기), `m칩.말id`, `a증강키`, `알번호,vx,vy`(알까기, 소수 셋째 자리 정수) 처럼 짧은 값만 쓴다.

## 순서·유실·중복
상태를 통째로 올리는 방식이라 메시지가 빠지거나 겹치거나 뒤바뀌어도 다음 갱신에서 메워진다.
- 줄은 항목 개수로 확인한다. `hv` 로 서로 몇 개까지 받았는지 알리고, 모자라는 사람이 있으면 그 부분을 창(window)으로 다시 올린다(최근 몇 개 + 모자라는 부분).
- 상태는 바뀐 직후 두 번 더 올리고, 변화가 없어도 2초마다 생존 신호를 올린다.
- 끊긴 사람의 줄은 다른 참가자가 대신 전해 준다(rl). 자기 기록을 잃고 돌아온 사람도 이 경로로 되찾는다.
- 상태 크기는 3.5 KB 이하로 맞춘다(실측 최대 2.6 KB).

## 난수·공정성
- 시드는 참가자 모두의 비밀 값으로 만든다: 먼저 `해시(비밀)`을 올리고, 모두 올린 뒤에 비밀을 공개해 합친다(방장도 못 고름).
- 이후 모든 난수(윷·증강 후보·AI)는 이 시드의 같은 수열에서 나오므로 어느 기기도 결과를 바꿀 수 없다(바꾸면 판 해시가 달라져 알림).
- 한계: 시드는 공개되므로 개발자 도구로 자기 클라이언트를 고친 사람은 앞으로 나올 윷을 미리 계산할 수 있다. 친구끼리 하는 용도에서는 이 정도로 충분하다고 판단했다.

## 재접속·되감기
- 입력 기록과 시작 정보를 이 기기에 저장한다. 새로고침·앱 종료 뒤 같은 방 코드로 이어하기 하면 기록으로 처음부터 빠르게 재생해 같은 지점까지 간다.
- 판 도중 한 사람이 사라지면 다른 사람이 '대신 두기'를 눌러 그 자리를 AI 로 바꾼다. AI 도 같은 난수로 돌아 모든 기기에서 같은 수를 둔다.
- 내가 입력한 뒤에 "그 자리를 AI 로" 명령이 늦게 도착하면(경쟁), 명령이 이긴다는 규칙으로 처음부터 되감아 다시 계산한다.
- 방장 개념은 대기실에서만 있다. 판이 시작되면 모두 같은 자격이라 방장이 나가도 판은 이어진다.

## 전송 선택
`#local` → 같은 브라우저 탭(시험) / `window.claude` 가 있으면 → Claude room / 그 밖 → MQTT.
- Claude room: 이름 붙은 방(`aug1-코드`)에 들어가 presence 로 상태를 올린다. 이름 붙은 방을 못 쓰는 보기에서는 로비 방에 코드를 달아 쓴다.
- MQTT: 공개 브로커 3곳(emqx, hivemq, mosquitto)에 동시에 붙고 모두에게 올린다. 한 곳이 죽어도 계속된다. retained 메시지로 늦게 온 사람도 최신 상태를 받고, 유언(LWT)으로 갑자기 끊긴 사람의 상태가 지워진다. 브라우저에서 쓰는 MQTT 클라이언트는 직접 만들었다(외부 스크립트 없음).

## 알려진 한계
- 비밀 선택(내려·명탐정·배달·계획대로·나 누구게?)은 화면에서만 가려질 뿐 네트워크에는 평문이다.
- 공개 MQTT 는 방 코드(4자리)를 아는 누구나 상태를 읽을 수 있다. 낯선 사람과 하는 용도가 아니다.
- 서로 다른 엔진(iPhone 사파리 = JavaScriptCore / 크롬 = V8)에서 같은 판이 나오도록 정렬 비교 함수 안의 난수, 삼각함수, 알까기 물리를 손봤고 시험했다. 그래도 실제 기기끼리의 확인은 별도로 필요하다. 어긋나면 해시 대조로 알린다.
- '대신 두기'와 본인의 입력이 거의 동시에 일어나면 그 사이에 둔 몇 수가 버려질 수 있다.
